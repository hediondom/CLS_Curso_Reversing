Hilo conductor multi-nivel y kit de plantillas C/C++

Propósito de esta sección transversal

Conectar de forma práctica los tres niveles del curso (Principiante, Intermedio y Avanzado). En la Parte I vemos cómo un único programa de validación (desde el check.c básico de la Etapa 1 hasta el componente BlocLab de las Etapas 2C, 2D y 6) cambia en el desensamblador y en el debugger a medida que evoluciona. En la Parte II tenés 5 plantillas mínimas en C y C++ listas para copiar y compilar en tu VM para practicar todas las lecciones intermedias y avanzadas sin depender de muestras externas.

Parte I · El hilo conductor: un mismo binario a través de los tres niveles

Una de las dificultades más comunes al estudiar reversing es sentir que cada tema nuevo (optimizaciones, TLS callbacks, packers, C++ con vtables, named pipes o drivers KMDF) pertenece a un mundo desconectado del anterior. Para unirlos, sigamos la misma regla de negocio en sus tres estadios de evolución:

Regla de negocio constante: aceptar dos enteros a y b tales que a <= 50 (0x32), b >= 50 (0x32) y (a + b) * 4 == 480 (0x1E0).

Estadio 1 · Nivel Principiante: check_v1.c con -O0 frente a -O2 (Etapas 1, 2A y 4.1)

En el nivel Principiante escribimos la función en C puro y comparamos qué genera el compilador en x64 sin optimizaciones (-O0 / /Od) frente a compilación optimizada (-O2):

// Regla base en C (Lecciones 1.5, 2.4, 2.8 y 4.1)
int validar_pares(int a, int b) {
    if (a > 50 || b < 50) return 0;
    return ((a + b) * 4) == 480;
}
Compilación sin optimizar (-O0, x64)          Compilación optimizada (-O2, x64)
──────────────────────────────────────────    ──────────────────────────────────────────
validar_pares:                                validar_pares:
  mov   dword ptr [rsp+8], ecx   ; guarda a     xor   eax, eax          ; resultado = 0 por defecto
  mov   dword ptr [rsp+10h], edx ; guarda b     cmp   ecx, 32h          ; ¿a > 50? (ECX = a)
  cmp   dword ptr [rsp+8], 32h   ; ¿a > 50?     jg    short salir       ; si a > 50, retorna 0
  jg    short fallo                             cmp   edx, 32h          ; ¿b < 50? (EDX = b)
  cmp   dword ptr [rsp+10h], 32h ; ¿b < 50?     jl    short salir       ; si b < 50, retorna 0
  jl    short fallo                             lea    ecx, [rcx+rdx]    ; ecx = a + b (con LEA, 2.2)
  mov   eax, dword ptr [rsp+8]                  cmp   ecx, 78h          ; ¡480 / 4 = 120 (0x78)!
  add   eax, dword ptr [rsp+10h] ; eax = a+b    sete  al                ; AL = 1 si (a+b)==120 (2.4)
  shl   eax, 2                   ; eax *= 4   salir:
  cmp   eax, 1E0h                ; ¿== 480?     ret
  jne   short fallo
  mov   eax, 1
  ret
fallo:
  xor   eax, eax
  ret

Qué aprende el alumno al comparar ambos listados:

  • Con -O0 (izquierda) cada variable baja al shadow space ([rsp+8], [rsp+10h], 1.2 y 2.5) y la multiplicación por 4 se ve como shl eax, 2 seguida de cmp eax, 1E0h.
  • Con -O2 (derecha) el compilador aplica reducción algebraica (2.8): en lugar de multiplicar (a + b) * 4 y comparar contra 480, suma con lea ecx, [rcx+rdx] y compara directamente contra 120 (0x78 = 480 / 4), usando sete al en vez de un salto condicional. Si en main se elige entre "Correcto" e "Incorrecto", -O2 carga ambas direcciones con lea y selecciona una con cmovne (4.1).

Estadio 2 · Nivel Intermedio: check_v2.c con TLS Callback, XOR y UPX (Etapas 2B, 2.17, 2.21 y 4.2)

En el nivel Intermedio, el mismo programa incorpora tres capas que frustran el camino directo de Principiante:

  1. Un TLS Callback previo a main (2.11 y 2.15): una función registrada en .CRT$XLB se ejecuta antes del entry point y consulta IsDebuggerPresent() (o lee gs:[60h] → [peb+2]). En lugar de mostrar un cartel evidente, si detecta un depurador cambia una variable global g_objetivo de 480 (0x1E0) a 999 (0x3E7). Quien pone el breakpoint directamente en main ve que 40 y 80 fallan sin entender quién alteró g_objetivo.
  2. Cadenas ocultas con XOR (2.10 y 4.2): la cadena "Correcto" ya no está en texto claro en .rdata; se almacena como {0x19, 0x35, 0x28, 0x28, 0x3F, 0x39, 0x2E, 0x35, 0x00} y un bucle corto aplica xor byte ptr [rcx+rax], 5Ah justo antes de imprimir.
  3. Empaquetado didáctico con UPX (2.17): al pasar el ejecutable por upx -9 check_v2.exe, las secciones originales se comprimen dentro de UPX1 y la IAT queda reducida a LoadLibraryA y GetProcAddress.
 Secuencia de resolución en el Nivel Intermedio:
 1. Triage PE-bear (1.4 / 2.17) ──► Secciones UPX0 (RawSize=0) y UPX1 (entropía 7,8)
 2. Desempaquetado en x64dbg (2.17) ──► Breakpoint de ejecución en memoria sobre UPX0
                                    ──► F9 hasta caer en el OEP ──► Dump + Scylla IAT Fix
 3. Inspección del Dump en IDA/Ghidra (2.11 / 2.16) ──► Directorio TLS apunta a tls_callback_0
                                                    ──► Se observa escritura a g_objetivo si BeingDebugged != 0
 4. Recuperación de cadena XOR (2.10 / 2.21) ──► Bucle xor [reg], 0x5A antes de puts
                                             ──► Breakpoint de log en x64dbg: "msg={s:rcx}"

Estadio 3 · Nivel Avanzado: BlocLab en C++, IPC y Kernel (Etapas 2C, 2D, 4.5, 5.2 y 6)

En el nivel Avanzado, la misma verificación vive dentro de una arquitectura realista de Windows:

  • Polimorfismo C++, RTTI, SSO y Excepciones (2.18 y 2D.11): un objeto derivado ValidadorBloc implementa el método virtual verificar(const std::string& etiqueta, const MensajeCLSF* m). En el listado vemos mov rax, [rcx] ; call qword ptr [rax+8]. Inspeccionando vtable[-1] en .rdata encontramos el _RTTICompleteObjectLocator (con RVAs en x64) que lleva al nombre .?AVValidadorBloc@@. Si los parámetros violan el rango, lanza una excepción C++ despachada por __CxxFrameHandler4 a través de .pdata y .xdata.
  • Protocolo binario CLSF sobre Named Pipe (4.5 y 2D.10): en lugar de pedir números por consola con scanf, un proceso servidor crea \.\pipe\BlocLabPipe (con FILE_FLAG_FIRST_PIPE_INSTANCE y PIPE_REJECT_REMOTE_CLIENTS) y recibe una trama CLSF cuyos campos en offset 0x08 y 0x0A transportan a y b en little-endian.
  • Auditoría de memoria y Kernel (2.19, 2.20 y 6.2): si el parser copia el cuerpo del mensaje sin validar body_len contra el tamaño del buffer reservado en el heap, diagnosticamos el desborde con Full Page Heap y WinDbg TTD (!heap -p -a y g-), comparamos el binario vulnerable (v1) contra el corregido (v2) con BinDiff / Version Tracking, y verificamos cómo el servidor consulta la versión del subsistema mediante DeviceIoControl(IOCTL_BLOCLAB_QUERY_VERSION = 0x80006000) hacia el driver KMDF de laboratorio.

Parte II · Kit de 5 plantillas de código mínimo (Boilerplates listos para compilar)

Todas las prácticas del curso están pensadas para ejecutarse sobre programas propios en tu VM aislada (Etapa 0). Para que no tengas que escribir desde cero cada escenario técnico, acá tenés cinco esqueletos autocontenidos de ~35 líneas en C y C++ estándar (también guardados como archivos sueltos en la carpeta plantillas_codigo/ del paquete HTML). Compilalos en la VM con Visual Studio Developer Command Prompt (cl.exe) o con MinGW-w64 (gcc / g++).

Plantilla 1 · check_evolucion.c (Práctica para 1.5, 2.4, 2.8, 2.10, 2.11, 2.15, 2.17 y 4.1)

Un único archivo en C que podés compilar en modo Principiante (por defecto) o en modo Intermedio (pasando /DMODO_INTERMEDIO o -DMODO_INTERMEDIO), lo que activa un TLS Callback que comprueba IsDebuggerPresent() y una rutina de descifrado XOR sobre el mensaje de éxito:

// Archivo: plantillas_codigo/check_evolucion.c
// Compilar Principiante (MSVC): cl /Zi /Od check_evolucion.c /Fe:check_v1_O0.exe
// Compilar Optimizado   (MSVC): cl /Zi /O2 check_evolucion.c /Fe:check_v1_O2.exe
// Compilar Intermedio   (MSVC): cl /Zi /O1 /DMODO_INTERMEDIO check_evolucion.c /Fe:check_v2.exe
// Compilar en MinGW-w64 (GCC) : gcc -O0 -g check_evolucion.c -o check_v1_O0.exe
#include <windows.h>
#include <stdio.h>
#include <stdlib.h>

static int g_objetivo = 480; // 0x1E0 en condiciones normales

#ifdef MODO_INTERMEDIO
static void NTAPI tls_antidebug(PVOID h, DWORD reason, PVOID res) {
    (void)h; (void)res;
    if (reason == DLL_PROCESS_ATTACH && IsDebuggerPresent()) {
        g_objetivo = 999; // Desvía la constante antes de entrar a main (Lecciones 2.11 y 2.15)
    }
}
#ifdef _MSC_VER
#pragma comment(linker, "/INCLUDE:_tls_used")
#pragma section(".CRT$XLB", long, read)
__declspec(allocate(".CRT$XLB")) PIMAGE_TLS_CALLBACK p_tls = tls_antidebug;
#else
PIMAGE_TLS_CALLBACK p_tls __attribute__((used, section(".CRT$XLB"))) = tls_antidebug;
#endif
#endif

int validar_pares(int a, int b) {
    if (a > 50 || b < 50) return 0;
    return ((a + b) * 4) == g_objetivo;
}

int main(int argc, char** argv) {
    int a = (argc > 2) ? atoi(argv[1]) : 0;
    int b = (argc > 2) ? atoi(argv[2]) : 0;
    if (argc <= 2) {
        printf("Primer valor: ");  if (scanf("%d", &a) != 1) return 1;
        printf("Segundo valor: "); if (scanf("%d", &b) != 1) return 1;
    }
    if (validar_pares(a, b)) {
#ifdef MODO_INTERMEDIO
        // "Correcto" cifrado con XOR 0x5A (Lecciones 2.10 y 4.2)
        unsigned char enc[] = {0x19, 0x35, 0x28, 0x28, 0x3F, 0x39, 0x2E, 0x35, 0x00};
        for (int i = 0; enc[i] != 0; ++i) enc[i] ^= 0x5A;
        puts((const char*)enc);
#else
        puts("Correcto");
#endif
        return 0;
    }
    puts("Incorrecto");
    return 1;
}

Plantilla 2 · cpp_rtti_sso.cpp (Práctica para 2.18 y 2D.11)

Genera en un solo binario: una jerarquía con herencia múltiple (para observar la vtable, el _RTTICompleteObjectLocator en vtable[-1] y un adjustor thunk sub rcx, 8), dos objetos std::string (uno corto en el buffer SSO de 16 bytes y otro largo en el heap), un std::vector<int> y un bloque try/catch con tablas en .pdata/.xdata:

// Archivo: plantillas_codigo/cpp_rtti_sso.cpp
// Compilar (MSVC FH4 actual): cl /EHsc /GR /Zi /O1 cpp_rtti_sso.cpp /Fe:cpp_fh4.exe
// Compilar (MSVC FH3 clásico): cl /EHsc /GR /Zi /O1 /d2FH4- cpp_rtti_sso.cpp /Fe:cpp_fh3.exe
// Compilar (MinGW ABI Itanium): g++ -O1 -g cpp_rtti_sso.cpp -o cpp_itanium.exe
#include <iostream>
#include <string>
#include <vector>
#include <stdexcept>
#include <typeinfo>

struct Componente {
    int id = 0x10;
    virtual ~Componente() = default;
    virtual int evaluar(int a, int b) const = 0;
};
struct Auditable {
    int nivel_log = 2;
    virtual void registrar(const char* evento) const { std::cout << "[LOG] " << evento << "\n"; }
};
class ValidadorBloc : public Componente, public Auditable {
    std::string etiqueta_corta = "BLOC_SSO";                        // < 16B: queda inline (SSO)
    std::string etiqueta_larga = "BLOC_CADENA_LARGA_EN_EL_HEAP_2026"; // >= 16B: reserva en heap
    std::vector<int> historial = {40, 80, 120};
public:
    int evaluar(int a, int b) const override {
        if (a < 0 || b < 0) throw std::runtime_error("Valores negativos no permitidos");
        return (a <= 50 && b >= 50 && (a + b) * 4 == (int)historial[2] * 4) ? 1 : 0;
    }
    void registrar(const char* ev) const override {
        std::cout << "[" << etiqueta_corta << "|" << etiqueta_larga.size() << "] " << ev << "\n";
    }
};

int main(int argc, char** argv) {
    Componente* obj = new ValidadorBloc();
    std::cout << "RTTI: " << typeid(*obj).name() << "\n";
    try {
        int res = obj->evaluar(argc > 1 ? std::stoi(argv[1]) : 40, 80);
        dynamic_cast<Auditable*>(obj)->registrar(res ? "OK" : "FALLO");
    } catch (const std::exception& ex) {
        std::cerr << "Excepcion capturada: " << ex.what() << "\n";
    }
    delete obj;
    return 0;
}

Plantilla 3 · heap_bug.c (Práctica para 2.19, 2.20 y 5.2)

Diseñada con un doble propósito: (1) activar Full Page Heap (gflags /p /enable heap_bug_v1.exe /full) y ver en WinDbg cómo el proceso se detiene exactamente en la instrucción que escribe más allá de los 16 bytes reservados (en vez de fallar más tarde en free), y (2) compilar una versión vulnerable (heap_bug_v1.exe) y una corregida con /DPARCHE_SEGURO (heap_bug_v2.exe) para comparar ambas en BinDiff / Ghidra Version Tracking (2.20):

// Archivo: plantillas_codigo/heap_bug.c
// Compilar v1 (vulnerable): cl /Zi /O1 heap_bug.c /Fe:heap_bug_v1.exe
// Compilar v2 (parcheada) : cl /Zi /O1 /DPARCHE_SEGURO heap_bug.c /Fe:heap_bug_v2.exe
// En la VM con Page Heap  : gflags /p /enable heap_bug_v1.exe /full
// Ejecutar en WinDbg      : heap_bug_v1.exe AAAAAAAAAAAAAAAAAAAA  --> !heap -p -a @rcx
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

typedef struct {
    char etiqueta[12];
    unsigned int estado;
} RegistroBloc; // sizeof(RegistroBloc) == 16 bytes exactos

int procesar_entrada(const char* entrada) {
    size_t len = strlen(entrada);
    RegistroBloc* reg = (RegistroBloc*)malloc(sizeof(RegistroBloc));
    if (!reg) return -1;
    reg->estado = 0xCAFE0001u;

#ifdef PARCHE_SEGURO
    // Versión v2 corregida: valida el límite antes de copiar (Lecciones 2.20 y 5.2)
    if (len >= sizeof(reg->etiqueta)) {
        puts("Error: entrada excede el buffer de 12 bytes");
        free(reg);
        return 1;
    }
    memcpy(reg->etiqueta, entrada, len + 1);
#else
    // Versión v1 con defecto didáctico: copia hasta 20 bytes en un bloque de 16 bytes (Lección 2.19)
    if (len > 20) len = 20;
    memcpy(reg->etiqueta, entrada, len);
    reg->etiqueta[11] = '\0';
#endif
    printf("Registro: %s | Estado: 0x%08X\n", reg->etiqueta, reg->estado);
    free(reg);
    return 0;
}

int main(int argc, char** argv) {
    const char* dato = (argc > 1) ? argv[1] : "BLOC_NORMAL";
    return procesar_entrada(dato);
}

Plantilla 4 · parser_clsf.c (Práctica para 4.1, 4.5 y 2.24)

Implementa el escritor y el lector del formato binario sintético CLSF de la lección 4.5 (12 bytes de cabecera + cuerpo variable). Si lo ejecutás con --gen muestra.clsf, genera la muestra exacta de 17 bytes vista en la teoría; si le pasás un archivo, valida cada campo y devuelve un código de estado distinto por cada fallo (ideal para confirmación diferencial en 4.1/4.5 y como harness en 2.24):

// Archivo: plantillas_codigo/parser_clsf.c
// Compilar (MSVC) : cl /Zi /O1 parser_clsf.c /Fe:parser_clsf.exe
// Compilar (MinGW): gcc -O1 -g parser_clsf.c -o parser_clsf.exe
// Generar muestra : parser_clsf.exe --gen muestra_A.clsf
// Analizar muestra: parser_clsf.exe muestra_A.clsf
#include <stdio.h>
#include <stdint.h>
#include <string.h>

#pragma pack(push, 1)
typedef struct {
    uint8_t  magic[4];   // +0x00: "CLSF" (43 4C 53 46)
    uint8_t  version;    // +0x04: 1
    uint8_t  flags;      // +0x05: 0
    uint16_t hdr_len;    // +0x06: 12 (0x000C LE)
    uint16_t body_len;   // +0x08: longitud del cuerpo (LE)
    uint16_t seq_id;     // +0x0A: campo variable / secuencia (0x002A = 42 LE)
} CabeceraCLSF;          // Total cabecera: 12 bytes
#pragma pack(pop)

int main(int argc, char** argv) {
    if (argc == 3 && strcmp(argv[1], "--gen") == 0) {
        CabeceraCLSF h = {{'C','L','S','F'}, 1, 0, 12, 5, 42};
        FILE* f = fopen(argv[2], "wb");
        if (!f) return 1;
        fwrite(&h, sizeof(h), 1, f);
        fwrite("HELLO", 1, 5, f);
        fclose(f);
        puts("Muestra CLSF de 17 bytes generada.");
        return 0;
    }
    if (argc < 2) { puts("Uso: parser_clsf [--gen salida.clsf | entrada.clsf]"); return 1; }
    FILE* f = fopen(argv[1], "rb");
    if (!f) return 2;
    uint8_t buf[256] = {0};
    size_t n = fread(buf, 1, sizeof(buf), f);
    fclose(f);
    if (n < sizeof(CabeceraCLSF)) { puts("Error: archivo truncado"); return 3; }
    const CabeceraCLSF* h = (const CabeceraCLSF*)buf;
    if (memcmp(h->magic, "CLSF", 4) != 0) { puts("Error: magic invalido"); return 4; }
    if (h->version != 1)                  { puts("Error: version no soportada"); return 5; }
    if (h->hdr_len != 12)                 { puts("Error: hdr_len != 12"); return 6; }
    if ((size_t)h->hdr_len + h->body_len > n) { puts("Error: body_len excede archivo"); return 7; }
    printf("CLSF OK | ver=%u flags=0x%02X seq=%u body(%u)=\"%.*s\"\n",
           h->version, h->flags, h->seq_id, h->body_len, h->body_len, (const char*)(buf + h->hdr_len));
    return 0;
}

Plantilla 5 · pipe_server_min.c (Práctica para 2D.1, 2D.10, 4.5 y 2.21)

Servidor local de Named Pipe en modo mensaje que aplica las banderas defensivas estudiadas en 2D.10 (FILE_FLAG_FIRST_PIPE_INSTANCE y PIPE_REJECT_REMOTE_CLIENTS) e implementa la máquina de estados de 4.5 (ESPERA_SALUDO → LISTO). Podés conectarte desde un script de Python en la misma VM e inspeccionar las llamadas con Process Explorer, WinDbg o Frida:

// Archivo: plantillas_codigo/pipe_server_min.c
// Compilar (MSVC) : cl /Zi /O1 pipe_server_min.c /Fe:pipe_server_min.exe
// Compilar (MinGW): gcc -O1 -g pipe_server_min.c -o pipe_server_min.exe
// Probar en Python: open(r'\\.\pipe\BlocLabPipe', 'r+b', buffering=0)
#include <windows.h>
#include <stdio.h>
#include <string.h>

int main(void) {
    const wchar_t* nombre = L"\\\\.\\pipe\\BlocLabPipe";
    HANDLE hPipe = CreateNamedPipeW(
        nombre,
        PIPE_ACCESS_DUPLEX | FILE_FLAG_FIRST_PIPE_INSTANCE,
        PIPE_TYPE_MESSAGE | PIPE_READMODE_MESSAGE | PIPE_WAIT | PIPE_REJECT_REMOTE_CLIENTS,
        1, 256, 256, 0, NULL);
    if (hPipe == INVALID_HANDLE_VALUE) {
        printf("CreateNamedPipeW fallo (GLE=%lu)\n", GetLastError());
        return 1;
    }
    puts("[ESPERA_SALUDO] Escuchando en \\\\.\\pipe\\BlocLabPipe ...");
    if (ConnectNamedPipe(hPipe, NULL) || GetLastError() == ERROR_PIPE_CONNECTED) {
        char buf[128] = {0};
        DWORD leidos = 0, escritos = 0;
        if (ReadFile(hPipe, buf, sizeof(buf) - 1, &leidos, NULL) && leidos >= 4 && memcmp(buf, "CLSF", 4) == 0) {
            puts("[LISTO] Saludo CLSF valido recibido; enviando respuesta fija.");
            const char resp[] = "CLSF_ACK_V1_READY";
            WriteFile(hPipe, resp, (DWORD)strlen(resp), &escritos, NULL);
        } else {
            const char err[] = "CLSF_ERR_BAD_HELLO";
            WriteFile(hPipe, err, (DWORD)strlen(err), &escritos, NULL);
        }
        FlushFileBuffers(hPipe);
        DisconnectNamedPipe(hPipe);
    }
    CloseHandle(hPipe);
    return 0;
}
